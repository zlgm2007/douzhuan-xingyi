# 斗转 · 北斗七星（146.56.251.169:8261）技术拆解与复刻方案

> 结论先写：这不是"北斗导航系统"，而是一个**纯前端自研的 WebGL 天文可视化 + 七个 UI 动效库的展示橱窗**。
> 页面标题 `斗转 · 北斗七星`，副标 `北斗七星 × Libraries.dev`，七个星对应七个 npm 动效库。
> 整个夜空**没有任何贴图、模型、HDRI、音频文件**——`assets/` 里只有 4 个 JS + 1 个 CSS，全部画面由着色器 + 5 万点粒子实时算出来。
> 复刻的真正门槛不在美术，在三处数学：赤道系→地平系变换、屏幕空间恒定宽度的长曝光弧、分层程序化氛围的一致性。

渲染器参数（复刻要一模一样才有那个味道）：

```js
new WebGLRenderer({ antialias:false, alpha:false, stencil:false, powerPreference:'high-performance' });
renderer.setClearColor('#000000');
```

## 三、六段核心着色器（这是复刻的全部内容）

### 1. 天空：`skyBase()` —— 所有氛围的公共地基

天空不是贴图，是函数。天顶/中层双色渐变 + 地平气辉 + 低频噪声 + 东北低空一团暖色城镇光：

```glsl
vec3 skyBase(vec3 d){
  float a = clamp(d.y, 0.0, 1.0);                  // 高度角正弦
  vec3 zenith = vec3(0.0035,0.0048,0.0105);
  vec3 mid    = vec3(0.010,0.014,0.028);
  vec3 col    = mix(mid, zenith, smoothstep(0.0,0.62,a));
  col += vec3(0.020,0.028,0.052) * exp(-a*7.5);    // 地平气辉带
  col += vec3(0.006,0.008,0.016) * (snoise(d*3.1)*0.5+0.5);
  // 城镇光（东北低空，az≈0.95 rad）
  float az = atan(d.x, -d.z);
  float w  = exp(-pow((az-0.95)/0.38, 2.0)) * exp(-a*18.0);
  col += vec3(0.32,0.14,0.05) * w * 0.18;
  return col;
}
```

**关键设计**：远山、水面都用同一个 `skyBase()` 采样。所以"山比天黑但透着天光""水面映着地平线余晖"是天然一致的——这是整套画面风格统一的秘诀，不是调色调出来的。

### 2. 银河：在**银道坐标**里画条带

```glsl
vec3 g = uEqToGal * d;              // 赤道 → 银道
float b = asin(g.z);                // 银纬
float l = atan(g.y, g.x);            // 银经
float center = ...;                 // 靠近银心的权重
float width = mix(0.07, 0.19, center*center);
float band  = exp(-pow(b/width, 2.0));
float warp  = fbm(g*2.3);           // 条带扭曲
float cloud = fbm(g*4.6);           // 大云团
float fine  = fbm(g*15.0);          // 细节
float lane  = fbm(g*7.2);           // 暗尘带
color = mix(vec3(0.40,0.50,0.88), vec3(1.0,0.84,0.66), warm) + 粉红氢区
```

五层噪声频率 `2.3 / 4.6 / 15.0 / 7.2` 是原站参数，`uMilkyGain` 只是给这个结果调增益——**没有一张银河照片贴图**。

### 3. 星场：5 万颗星，一次 draw call

- attributes：`aDir`(方向) `aColor`(颜色) `aMag`(星等) `aSeed`(闪烁相位)，几何体是 5 万个点。
- 星等 → 通量：`f = pow(10, -0.4*(m-1))`
- 点径：`clamp(2.1 + 3.4*pow(f,0.42), 2, 11) * pixelRatio`
- 亮度：`clamp(pow(f,0.45)*1.45, 0, 1.6)`
- 闪烁：**双正弦叠加**，且越近地平振幅越大：`amp *= 1 - smoothstep(0, 0.55, alt)`
- 片元是**解析光斑**，不是贴图 sprite：
  ```glsl
  float core = exp(-d2*3.2);
  float halo = exp(-sqrt(d2)*3.0)*0.22;
  if (d2 > 1.0) discard;   // 圆外丢弃，避免方块
  ```

星色是真物理：**B-V 色指数 → 黑体色温 → RGB**，再中心化、提饱和 1.55 倍：

```js
const T = 4600 * (1/(0.92*bv + 1.7) + 1/(0.92*bv + 0.62));
// T → RGB（黑体轨迹近似），然后
rgb = normalize((rgb - mean) * 1.55 + mean)
```

### 4. 长曝光星轨：全篇最巧的一段

不是"拍多帧累积"，而是**实例化几何 + 屏幕空间切线**：

- 每颗星一条 44 段的四边形带（`InstancedBufferGeometry`，属性 `aS: 0→1`、`aSide: ±1`）。
- 顶点着色器用 `clipAt(s) = project(rotZ(aDir, -uExposure*s))` 采样弧上三个点，**把前后点的 NDC 差分当作屏幕空间切线**：

```glsl
vec2 dir = (ndcNext - ndcPrev) * uResolution;
vec2 nrm = vec2(-dir.y, dir.x);                  // 垂直于弧
c.xy += nrm * aSide * width / uResolution * c.w; // 按 w 撑开，保证固定像素宽
```

→ 弧线在屏幕上**恒定像素宽度**，不会因为透视变细。`uExposure` 一个 uniform 就是"快门开了多久"，整片星轨随之旋转。亮度沿弧衰减（头亮尾淡）。

### 5. 七颗亮星：十字星芒

```glsl
float spike = (exp(-abs(q.x)*90.0) + exp(-abs(q.y)*90.0)) * pow(1.0-r, 3.0) * vSpike;
float core  = exp(-r*r*160.0) * 3.0;
```
另有 `uIgnite[7]`（逐颗点火）、`uHover`、`uZoom/uZoomStar`（点星时镜头推进）。

### 6. 远山 / 水面

- 远山 3~4 层剪影，参数化：`dist 620/400/240/120`、各自的 `base/amp/freq/seed/haze`；颜色 `skyBase(身后方向)*0.62` 混 `rock = vec3(0.0016,0.0022,0.0038)`，近处叠谷底薄雾（`snoise`）。→ "比天暗但透天光"。
- 水面：反射方向 `R = vec3(V.x, -V.y, V.z)`（V = 世界点 - 相机），再经两层 `snoise` 涟漪扰动，远处变平，`fade` 让近处与边缘淡出。地平线处的"水 + 倒影"是夜景氛围成立的关键。

## 四、天文数学（专业感的真正来源）

### 赤道 → 地平

```glsl
vec3 skyAt(vec3 e, float lst){
  float c = cos(-lst), s = sin(-lst);
  vec3 v = vec3(c*e.x - s*e.y, s*e.x + c*e.y, e.z);  // 绕天极旋转
  return uFrame * v;                                  // 纬度矩阵：x→东, y→天顶, z→南
}
```

> ⚠️ 复刻踩坑记录：赤道 x 轴指向 **RA=0（春分点）**，地平 x 轴指向 **东**，两者手性相反。
> 矩阵第一行必须是 `[-sin(lst), cos(lst), 0]`（东分量 = cos(lst)·y − sin(lst)·x）。写成 `[sin, -cos, 0]` 整个星空东西镜像，北斗七星会跑到画面反侧。

`uFrame = [[-b, a, 0],[a*c, b*c, s],[a*s, b*s, -c]]`，其中 `a=cos(lst) b=sin(lst) c=cos(lat) s=sin(lat)`。
纬度按登封 **34.4°N**（原站显示 34°24′，shader 里按 34° 估算）。

### 大气消光：Kasten & Young 1989

```glsl
float X = 1.0 / (max(y,0.0) + 0.50572 * pow(altDeg + 6.07995, -1.6364));  // 大气质量
float m = aMag + 0.26 * (X - 1.0);                                        // 消光后星等
```
星星越贴地平越暗越红——这一条让"真实感"立刻拉开与普通星空 demo 的差距。

### 恒星时是全局时钟

`lst` 是唯一的时间轴：拖拽 → 改 `lst` → 星空整体绕天极转 → 节气/斗柄指向/罗盘指针全部由它派生。
所以"斗转星移"不是动画，是天文计算。

### 拖拽不是"改角度"，是"速度积分 + 速度驱动曝光"

这是"斗转星移、时光飞逝"全部手感的来源，也是原站最容易被漏掉的一段（反编译 `index-Da7x7gq4.js` 得到）：

```js
// 指针移动：只算角速度，不直接改角度
v = dx / window.innerWidth * 9 * (1000 / dtMs) * 0.12;
velocity += (v - velocity) * 0.5;          // 一阶平滑，避免手的抖动

// 每帧
if (!dragging) velocity *= Math.exp(-dt * 1.6);   // 松手 → 惯性指数衰减
base = longExposure ? 0.42 : 0.004;               // 常驻时间流速（不拖也在走）
lst += (velocity + base) * dt;                    // 星空转过多少

longAcc = longExposure ? min(longAcc + |p| * dt, 2π)
                       : longAcc * Math.exp(-dt * 2.4);
m = min(|velocity| * 0.16, 1.4);                  // 拖得越快，曝光越长
exposure += (max(m, longAcc) - exposure) * (1 - Math.exp(-dt * 10));
```

三个关键点：

1. **速度直接映射成 `uExposure`**（星轨长度）。所以拖得越快，星点被拉成越长的弧——这就是"飞逝"的视觉本体，而不是单纯把画面转快。
2. **松手后 `exp(-1.6t)` 衰减**，弧线随之缩短、回落到静止星点，形成"余韵"。
3. **`base = 0.004 rad/s` 常驻**：不拖也在走，约 55 倍实时（恒星时每秒跳 ~55 秒），所以画面永远"在流动"。

> 复刻时若只做"拖拽改 lst"，会得到一张转动很快但**没有拖影**的星空——用户一眼就能看出"缺了时光飞逝"。

## 六、音频引擎：16KB 搞定全部声音（零素材）

`class AudioEngine`，全部 WebAudio 程序化合成，没有任何 mp3/ogg：

```
master gain 0→0.9 (4s linearRamp)
  → DynamicsCompressor(threshold -18, ratio 3)
  → AnalyserNode(fftSize 1024)  ← 实时电平 → uniform uVoice
  → destination
```

| 层 | 内容 |
|---|---|
| 低频 drone | 73.42 / 110 / 146.83 / 220 Hz（D2/A2/D3/A3），每个 ±4 cents 双振荡器，增益 0.5/0.32/0.22/0.08 → `lowpass 380Hz Q0.6`；**0.045Hz LFO 调制截止频率**（8 秒一次"呼吸"） |
| 高音 shimmer | 587.33 / 880 / 1318.5 / 1479.98 / 1975.5 Hz，各自 0.05+n·0.031Hz 的 LFO 调增益（0.005 级，极轻） |
| 噪声 | 4s buffer 用 7 个一极点滤波器叠成近似 pink noise → `bandpass 420Hz Q0.5`，增益 0.018，0.07Hz LFO |
| 拖拽摩擦声 | noise → `bandpass(300Hz, Q1.4)` → `scrubGain`（拖动速度驱动） |
| 和声 swell | 293.66 / 440 / 659.25 / 739.99（D4/A4/E5/F#5），各 0.03 |
| 点击 chime | `chime(freq,0.5,4.5,pan)`：正弦 + `freq*3.53` 泛音，`exponentialRamp` 4.5s 衰减 + `StereoPanner` |
| 混响 | **程序化 impulse**：`(Math.random()*2-1)*(1-e/r)**2.6`，4.8s，`ConvolverNode` |

**最妙的一处**：`AnalyserNode` 的实时电平喂给 `uVoice` uniform →
**声音驱动星星闪烁幅度、银河增益、水面涟漪**。"七个会呼吸的界面"里的"呼吸"是真的声音联动。

## 八、复刻方案

### 8.1 选型建议

| 方案 | 适用 | 代价 |
|---|---|---|
| **A. 单文件 HTML + three.js importmap**（已采用） | 想快速验证画面质感、零构建、可离线 | 无 HMR，模块化差 |
| B. Vite + React + R3F + @react-three/postprocessing | 要 1:1 对齐原站（含七个星室、zustand 快照） | 构建链 + 依赖体积 |
| C. 现成星空库（stellarium-web / d3-celestial） | 只要"能看星座" | 拿不到这套程序化氛围与长曝光弧线 |

> 结论：**画面那 90% 只能自己写 shader**，任何库都替代不了 `skyBase()` + 程序化银河 + 屏幕空间星轨。

### 8.2 里程碑拆解（建议顺序，别倒着做）

| 阶段 | 内容 | 验收标准 | 估时 |
|---|---|---|---|
| M0 地基 | 天球 + `skyBase()` + 后处理链 | 一片有层次的夜空，无贴图 | 0.5 天 |
| M1 天文坐标 | 恒星时 / 赤道→地平矩阵 / 消光 | 拖拽时星空绕天极正确旋转，东西不镜像 | 1 天（**最容易翻车**）|
| M2 星场 | 5 万点 + B-V 配色 + 双正弦闪烁 | 星河有颗粒感、地平附近更闪 | 1 天 |
| M3 银河+地景 | 银道条带 5 层 fbm；远山 3 层；水面倒影 | 山/水/天同一个 `skyBase`，风格统一 | 1.5 天 |
| M4 北斗 | 七颗星档案 + 连线 + 指极虚线 + 星芒 | 七星可点、可看数据卡 | 1 天 |
| M5 长曝光 | 实例化 ribbon + NDC 差分切线 | 弧线恒宽、绕极同心 | 1.5 天 |
| M6 HUD | 节气 / 斗柄 / 罗盘 / 恒星时 / 曝光计时 | 文案与排版对齐原站 | 0.5 天 |

### 8.3 复刻清单（可直接照抄的参数）

```js
// 相机 / 渲染器
fov 58, near 0.5, far 4000, position [0,3,0], dpr 上限 1.75
// 天球
SphereGeometry(900*1.05, 64, 32), BackSide, depthWrite:false, renderOrder:-10
// 星场
gl_PointSize = clamp(2.1 + 3.4*pow(f,0.42), 2, 11) * pxRatio
alpha        = clamp(pow(f,0.45)*1.45, 0, 1.6) * (1 - smoothstep(0,0.55,alt))
// 消光
X = 1/(max(y,0)+0.50572*pow(altDeg+6.07995,-1.6364));  m = mag + 0.26*(X-1)
// 星轨
段数 44，宽度 clamp(0.55+0.85*pow(f,0.35), .5, 1.9) px，uExposure 驱动旋转
// 银河
fbm 五层 2.3 / 4.6 / 15.0 / 7.2，纬度带宽 mix(0.07, 0.19, center^2)
// Bloom
intensity 1.15, threshold 0.12, smoothing 0.35, radius 0.78, mipmapBlur
```

### 8.4 五个已知坑（都是踩过的）

1. **东西向符号**：`[-sin(lst), cos(lst), 0]` 而不是 `[sin, -cos, 0]`；错一处整片星空镜像。
2. **山脊接缝**：用 `Math.sin(x*f)` 拼随机频率会在 0/2π 处断线；改成**整数频次三角级数**（K = 1,2,3,5,8,13,21）即连续。
3. **水面反射**：`R.y` 必须 `max(R.y, 0.03~0.10)`，否则近处反射天顶 = 纯黑，地平下方发紫。
4. **composer 下 `renderer.info.render.calls` 恒为 1**：它统计最后一次 pass，不代表真实开销；要诊断就用投影坐标数组核对屏幕位置。
5. **长曝光 ribbon 的宽度**：必须用 `nrm * width / uResolution * c.w` 走屏幕空间，用世界空间会随距离变细。

## 十、一句话总结

这套东西的本质是 **"一个 900 半径的天球 + 一套自己写的天文数学 + 5 万点 GPU 粒子 + 一组程序化噪声"**：
素材成本为零，门槛全在 GLSL 与坐标变换；学到的最大一招是**让天空、银河、远山、水面共享同一个 `skyBase()`**，
以及**用屏幕空间切线把星轨宽度锁死**。这两点做到，画面质感立刻到原作水平。
